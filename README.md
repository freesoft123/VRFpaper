# VRF-APF: Vector Repulsive-Force Planning for Escape from U-Shaped Enclosures

This repository contains the simulation, data-processing, and plotting code for the manuscript
*Research on Path-Planning Algorithms Based on Vector Computing*. The project addresses the local
planning problem in which a robot must escape from the interior of a U-shaped enclosure through an
opening. It compares several artificial potential field (APF) methods in 2D and 3D geometries and
under different kinematic models.

## Research Overview

VRF-APF aggregates the vector repulsive forces generated by discrete obstacle points along the
enclosure boundary to construct an escape force field. Inside the U-shaped enclosure, the method
does not use a goal attractive force. When local stagnation is detected, the adjustment coefficient
lambda is decreased stepwise to change the direction of the resultant force until the robot crosses
the opening.

The following five planners are compared:

| Method | Description                                                              |
| --- |--------------------------------------------------------------------------|
| SOPC-APF | Predictive-collision and virtual-target APF                              |
| DIT-APF | APF with dynamic parameters, tangential forces, and inertia-related terms |
| RV-APF | Rotating-vector repulsive-force APF                                      |
| SA-MAPF | Simulated-annealing APF with virtual-target and fuzzy corrections        |
| VRF-APF | Vector-repulsive-force APF proposed in this work                         |

Two kinematic-model categories are considered:

- **Holonomic kinematic model:** the robot can move directly along the direction of the resultant force.
- **Simplified bicycle / 3D-YPN:** the 2D simplified bicycle kinematic model and a three-dimensional
  yaw--pitch nonholonomic kinematic model (3D-YPN).

## Experimental Setup

- Each scenario uses 100 randomized start positions.
- Five fixed exterior target points are assigned to each scenario.
- Opening widths are 3, 5, 8, and 10 m.
- The minimum required clearance is 0.5 m.
- The maximum number of planning iterations is 3,000.
- Both holonomic and nonholonomic kinematic models are evaluated.
- A total of 80,000 individual simulation runs are performed across the 2D and 3D scenarios.

The main VRF-APF parameters are:

```text
lambda_0 = 0.8
delta_lambda = 0.1
lambda_min = 0.3
W = 50 steps
tau = 0.1 m
F_th = 1e-12
```

Here, `W` is the stagnation-detection window, `tau` is the displacement threshold over that
window, and `F_th` is the threshold below which the resultant force is treated as approximately
zero.

## Evaluation Metrics

Five metrics are used to compare the planners:

1. **Success count:** number of runs in which the robot crosses the opening while maintaining at
   least 0.5 m clearance from the enclosure boundary throughout the trajectory.
2. **Collision count:** number of runs in which the minimum boundary clearance falls
   below 0.5 m.
3. **Mean exit-opening deviation:** mean distance between the crossing point and the center of the
   opening for successful escapes.
4. **Iteration count:** number of planning iterations from the initial position to opening
   for successful escapes.
5. **Per-step computation time:** mean time required to compute one resultant force and update the
   robot state once, in milliseconds.

## Selected Results

Results obtained by VRF-APF are summarized below:

| Scenario | Holonomic model | Nonholonomic model | Main failure modes |
| --- | ---: | ---: | --- |
| Rectangular enclosure (2D) | 2,000/2,000 | 1,995/2,000 | Five collision-free stagnations |
| Hexagonal enclosure (2D) | 2,000/2,000 | 1,990/2,000 | Ten collision events |
| Cuboid enclosure (3D) | 2,000/2,000 | 1,955/2,000 | 45 maximum-iteration terminations |
| Hexagonal-frustum enclosure (3D) | 1,500/2,000 | 1,500/2,000 | Zero-force stagnation or maximum-iteration termination at the 3 m opening |

## Environment and Installation

Python 3.9 or later is recommended.

```bash
python3 -m venv .venv
source .venv/bin/activate

python -m pip install -r requirements.txt
```

## Usage

### Five planners, five targets, and four opening widths in 2D

```bash
python3 simulation/five_methods_goal_sim.py \
  --outdir simulation/outputs/five_methods_goals_all_gaps
```

### Five planners, five targets, and four opening widths in 3D

```bash
python3 simulation/three_d_five_methods_goal_sim.py \
  --outdir simulation/outputs/three_d_five_methods
```

All Python modules required by the 3D simulations are included under
`simulation/`; scene and random-start data required by those modules are stored under
`simulation/outputs/`.

## Data

The primary raw data files are:

- `simulation/outputs/five_methods_goals_all_gaps/five_methods_goals_results.json`
- `simulation/outputs/five_methods_goals_all_gaps/five_methods_goals_results.csv`
- `simulation/outputs/three_d_five_methods/three_d_five_methods_results.json`

Each JSON file stores both the per-run simulation records and the aggregate statistics grouped by
geometry, target, planner, and kinematic model. The 2D and 3D experiments each contain 40,000 runs,
giving 80,000 runs in total.
